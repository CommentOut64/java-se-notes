## 1. Collection 子接口二：Set

### 1.1 Set 接口概述

`java.util.Set` 接口是 `java.util.Collection` 接口的一个子接口。它继承了 `Collection` 接口的所有方法，没有在此基础上额外定义新的方法。

`Set` 接口的主要特点是：

*   **不允许重复元素**：`Set` 集合中不能包含两个通过 `equals()` 方法判断为相等的元素。如果尝试添加一个已经存在的元素 (根据 `equals()` 判断)，则添加操作会失败，原集合保持不变。
*   **通常无序**：大多数 `Set` 实现类 (如 `HashSet`) 不保证元素的排列顺序，即元素的存储和迭代顺序可能与添加顺序不同。但某些特定实现 (如 `LinkedHashSet` 和 `TreeSet`) 可以维护特定顺序。

`Set` 集合支持的遍历方式与 `Collection` 集合一致，主要有：

*   增强 for 循环 (foreach)。
*   使用迭代器 (`Iterator`)。

`Set` 接口的常用实现类有：

*   `HashSet`：基于哈希表实现，无序。
*   `LinkedHashSet`：基于哈希表和链表实现，维护元素的添加顺序。
*   `TreeSet`：基于红黑树实现，元素按自然顺序或自定义顺序排序。

## 2. Set 的主要实现类：HashSet

### 2.1 HashSet 概述

`HashSet` 是 `Set` 接口最常用的实现类，它基于哈希表 (实际上是一个 `HashMap` 实例) 来存储元素。

**主要特点**：

*   **无序性**：`HashSet` 不保证元素的迭代顺序与插入顺序一致。元素的存储位置由其 `hashCode()` 值决定。
*   **不允许重复元素**：通过元素的 `hashCode()` 和 `equals()` 方法来确保唯一性。
*   **高效性**：对于基本的添加 (`add`)、删除 (`remove`) 和查找 (`contains`) 操作，`HashSet` 通常能提供常数时间复杂度 O(1) 的性能 (前提是哈希函数设计良好，元素均匀分布)。
*   **非线程安全**：如果在多线程环境下使用，需要外部同步处理，或者使用 `Collections.synchronizedSet()` 方法包装，或使用 `java.util.concurrent` 包中的并发 Set 实现。
*   **允许 `null` 元素**：`HashSet` 最多可以存储一个 `null` 元素。

**判断元素相等的标准**：
`HashSet` 判断两个元素是否相等的标准是：
1.  两个对象的 `hashCode()` 方法返回的哈希值相等。
2.  并且，这两个对象的 `equals()` 方法返回 `true`。

因此，对于存放在 `HashSet` 中的自定义类的对象，**该类必须正确地重写 `hashCode()` 和 `equals(Object obj)` 方法**，以确保集合能正确处理元素的唯一性。通常遵循“相等的对象必须具有相等的哈希码”原则。

### 2.2 HashSet 添加元素的内部机制

当向 `HashSet` 中添加一个元素时，其大致过程如下：
1.  调用该元素的 `hashCode()` 方法获取其哈希码。
2.  根据哈希码计算出该元素在 `HashSet` 底层数组中的存储位置 (桶索引)。
3.  **检查该位置**：
    *   如果该位置没有其他元素，则直接将新元素存入该位置。
    *   如果该位置已经存在一个或多个元素 (哈希冲突)，则会遍历该位置上的链表 (或红黑树，JDK 8+ 中当链表长度超过一定阈值时会转换为红黑树以优化性能)。
    *   在遍历过程中，如果发现其中某个元素与新元素的哈希码相同，并且通过 `equals()` 方法比较也返回 `true`，则认为新元素已存在，添加失败。
    *   如果遍历完所有元素都没有找到与新元素 `equals()` 相等的元素，则将新元素添加到该位置的链表 (或红黑树) 的末尾。

### 2.3 hashCode() 与 equals() 的重写

正确重写 `hashCode()` 和 `equals()` 方法对于 `HashSet` (以及其他依赖哈希机制的集合如 `HashMap`) 的正确运作至关重要。

**`hashCode()` 方法重写原则**：
*   **一致性**：在程序执行期间，只要对象的 `equals()` 方法比较所用的信息没有被修改，那么对这同一个对象无论调用多少次 `hashCode()` 方法，都必须始终返回同一个整数。
*   **等同性**：如果两个对象通过 `equals(Object)` 方法比较是相等的，那么调用这两个对象中任意一个对象的 `hashCode()` 方法都必须产生同样的整数结果。
*   **不等不等性 (非强制)**：如果两个对象通过 `equals(Object)` 方法比较是不相等的，那么调用这两个对象中任意一个对象的 `hashCode()` 方法，不要求必须产生不同的整数结果。但是，程序员应该意识到，为不相等的对象生成不同整数结果可以提高哈希表的性能。
*   通常，参与 `equals()` 方法比较的字段都应该用来计算 `hashCode()` 值。

**`equals()` 方法重写原则**：
*   **自反性**：对于任何非 `null` 的引用值 `x`，`x.equals(x)` 必须返回 `true`。
*   **对称性**：对于任何非 `null` 的引用值 `x` 和 `y`，当且仅当 `y.equals(x)` 返回 `true` 时，`x.equals(y)` 必须返回 `true`。
*   **传递性**：对于任何非 `null` 的引用值 `x`、`y` 和 `z`，如果 `x.equals(y)` 返回 `true`，并且 `y.equals(z)` 返回 `true`，那么 `x.equals(z)` 必须返回 `true`。
*   **一致性**：对于任何非 `null` 的引用值 `x` 和 `y`，只要 `equals` 的比较操作在对象中所用的信息没有被修改，多次调用 `x.equals(y)` 就会一致地返回 `true`，或者一致地返回 `false`。
*   **非空性**：对于任何非 `null` 的引用值 `x`，`x.equals(null)` 必须返回 `false`。
*   通常建议在重写 `equals()` 方法时，也同时重写 `hashCode()` 方法。现代 IDE (如 IntelliJ IDEA, Eclipse) 提供了自动生成这两个方法的功能，可以作为很好的起点。

> **注意**：如果修改了已存入 `HashSet` 的对象中参与 `equals()` 和 `hashCode()` 计算的属性，可能会导致该对象在集合中“丢失”(即 `contains()` 返回 `false`，`remove()` 失败)，或者导致集合的行为变得不可预测。因此，通常不建议修改存放在哈希集合中对象的关键属性，或者在修改前先从集合中移除该对象。

### 2.4 HashSet 示例

**存储自定义对象 (需重写 `equals` 和 `hashCode`)**：
```java
import java.util.Objects;
import java.util.HashSet;
import java.util.Set;

class MyDate {
    private int year;
    private int month;
    private int day;

    public MyDate(int year, int month, int day) {
        this.year = year;
        this.month = month;
        this.day = day;
    }

    // Getters...

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (o == null || getClass() != o.getClass()) return false;
        MyDate myDate = (MyDate) o;
        return year == myDate.year && month == myDate.month && day == myDate.day;
    }

    @Override
    public int hashCode() {
        return Objects.hash(year, month, day); // 使用 Objects.hash() 方便生成
    }

    @Override
    public String toString() {
        return "MyDate{" + "year=" + year + ", month=" + month + ", day=" + day + '}';
    }
}

public class TestHashSetCustomObject {
    public static void main(String[] args) {
        Set<MyDate> set = new HashSet<>();
        set.add(new MyDate(2024, 6, 2));
        set.add(new MyDate(2024, 6, 2)); // 重复元素，添加失败
        set.add(new MyDate(2025, 1, 1));

        System.out.println(set);
        // 输出可能类似: [MyDate{year=2025, month=1, day=1}, MyDate{year=2024, month=6, day=2}]
        // 顺序不保证
    }
}
```

### 2.5 HashSet 相关应用示例

*   **List 去重**：利用 `HashSet` 不允许重复元素的特性，可以方便地为 `List` 去重。
    ```java
    import java.util.ArrayList;
    import java.util.HashSet;
    import java.util.List;
    import java.util.Set;
    
    public class ListDeduplication {
        public static <T> List<T> deduplicate(List<T> list) {
            Set<T> set = new HashSet<>(list); // 直接用 List 初始化 HashSet
            return new ArrayList<>(set);      // 再转回 ArrayList (顺序可能改变)
        }
    
        public static void main(String[] args) {
            List<Integer> numbers = new ArrayList<>();
            numbers.add(1);
            numbers.add(2);
            numbers.add(2);
            numbers.add(3);
            List<Integer> uniqueNumbers = deduplicate(numbers);
            System.out.println(uniqueNumbers); // 输出: [1, 2, 3] (顺序可能不同)
        }
    }
    ```

*   **生成不重复随机数**：
    ```java
    import java.util.HashSet;
    import java.util.Random;
    import java.util.Set;
    
    public class UniqueRandomNumbers {
        public static void main(String[] args) {
            Set<Integer> uniqueRandoms = new HashSet<>();
            Random random = new Random();
            int targetSize = 10;
            int upperBound = 20; // 生成 1 到 20 的随机数
    
            while (uniqueRandoms.size() < targetSize) {
                int num = random.nextInt(upperBound) + 1;
                uniqueRandoms.add(num);
            }
    
            System.out.println("Generated unique random numbers: " + uniqueRandoms);
        }
    }
    ```

## 3. Set 的实现类之二：LinkedHashSet

`LinkedHashSet` 是 `HashSet` 的一个子类。它与 `HashSet` 的主要区别在于：

*   **维护插入顺序**：`LinkedHashSet` 在内部除了使用哈希表来存储元素外，还额外使用了一个双向链表来记录元素的插入顺序。因此，当迭代 `LinkedHashSet` 时，元素将按照它们被添加到集合中的顺序出现。
*   **性能**：由于维护了额外的链表，`LinkedHashSet` 的插入和删除操作的性能通常会略低于 `HashSet` (但仍然是常数时间复杂度)。然而，其迭代性能通常优于 `HashSet`，因为迭代是沿着链表进行的，而不是遍历哈希表的桶。

其他方面，如不允许重复元素、允许 `null` 元素、非线程安全等特性与 `HashSet` 相同。

**示例**：
```java
import java.util.LinkedHashSet;
import java.util.Set;

public class TestLinkedHashSetOrder {
    public static void main(String[] args) {
        Set<String> set = new LinkedHashSet<>();
        set.add("Apple");
        set.add("Banana");
        set.add("Cherry");
        set.add("Apple"); // 重复，添加失败

        System.out.println(set); // 输出: [Apple, Banana, Cherry] (按添加顺序)
    }
}
```

## 4. Set 的实现类之三：TreeSet

### 4.1 TreeSet 概述

`TreeSet` 是 `java.util.SortedSet` 接口的实现类 (同时也是 `java.util.NavigableSet` 接口的实现类)，它能确保集合中的元素处于排序状态。

**主要特点**：

*   **有序性**：`TreeSet` 中的元素会自动按照某种顺序进行排序。默认情况下，是元素的自然顺序 (natural ordering)，或者可以通过在构造 `TreeSet` 时提供一个 `Comparator` 来指定自定义顺序。
*   **不允许重复元素**：`TreeSet` 通过比较方法 (如 `compareTo()` 或 `compare()`) 的返回值为 0 来判断元素是否相等，从而确保元素的唯一性。
*   **底层结构**：`TreeSet` 底层使用红黑树 (a self-balancing binary search tree) 结构来存储元素，这保证了其增、删、查操作的时间复杂度为 O(log n)。
*   **元素类型要求**：
    *   如果使用自然排序，添加到 `TreeSet` 中的元素必须实现 `java.lang.Comparable` 接口。
    *   所有添加到 `TreeSet` 中的元素必须是可相互比较的 (通常是同一类型的对象)，否则会在运行时抛出 `ClassCastException`。
*   **非线程安全**。

### 4.2 排序机制

`TreeSet` 支持两种排序方式：

1.  **自然排序 (Natural Ordering)**：
    *   要求添加到 `TreeSet` 中的元素的类实现 `Comparable` 接口，并重写其 `compareTo(Object obj)` 方法。
    *   `compareTo()` 方法定义了对象之间的比较规则。例如，返回负整数表示当前对象小于参数对象，返回零表示相等，返回正整数表示当前对象大于参数对象。
    *   `TreeSet` 会使用此方法来确定元素的顺序和唯一性。

2.  **定制排序 (Custom Ordering)**：
    *   如果在创建 `TreeSet` 时，向其构造器传入一个实现了 `java.util.Comparator` 接口的对象，则 `TreeSet` 会使用该 `Comparator` 的 `compare(T o1, T o2)` 方法来比较元素。
    *   这允许在元素类本身没有实现 `Comparable` 接口，或者希望使用不同于自然顺序的排序规则时，进行自定义排序。

### 4.4 TreeSet 示例

**自然排序 (自定义类实现 `Comparable`)**：
```java
import java.util.TreeSet;
import java.util.Set;
import java.util.Objects;

class User implements Comparable<User> {
    private String name;
    private int age;

    public User(String name, int age) {
        this.name = name;
        this.age = age;
    }

    // Getters...

    @Override
    public String toString() {
        return "User{" + "name='" + name + '\'' + ", age=" + age + '}';
    }

    // 按年龄升序排序，年龄相同则按姓名升序排序
    @Override
    public int compareTo(User other) {
        if (this.age != other.age) {
            return Integer.compare(this.age, other.age);
        }
        return this.name.compareTo(other.name);
    }

    @Override
    public boolean equals(Object o) { // equals 和 hashCode 最好也重写，尽管 TreeSet 主要依赖 compareTo
        if (this == o) return true;
        if (o == null || getClass() != o.getClass()) return false;
        User user = (User) o;
        return age == user.age && Objects.equals(name, user.name);
    }

    @Override
    public int hashCode() {
        return Objects.hash(name, age);
    }
}

public class TestTreeSetNaturalOrder {
    public static void main(String[] args) {
        Set<User> users = new TreeSet<>();
        users.add(new User("Alice", 30));
        users.add(new User("Bob", 25));
        users.add(new User("Charlie", 30));
        users.add(new User("Bob", 25)); // 重复，添加失败

        users.forEach(System.out::println);
        // 输出 (按年龄升序，年龄相同按姓名升序):
        // User{name='Bob', age=25}
        // User{name='Alice', age=30}
        // User{name='Charlie', age=30}
    }
}
```

**定制排序 (使用 `Comparator`)**：
```java
import java.util.TreeSet;
import java.util.Set;
import java.util.Comparator;

// User 类同上，但此时不一定需要实现 Comparable
public class TestTreeSetCustomOrder {
    public static void main(String[] args) {
        // 按姓名降序排序
        Comparator<User> nameDescendingComparator = new Comparator<User>() {
            @Override
            public int compare(User u1, User u2) {
                return u2.name.compareTo(u1.name); // 注意 u2 和 u1 的顺序实现降序
            }
        };

        Set<User> users = new TreeSet<>(nameDescendingComparator);
        users.add(new User("Alice", 30));
        users.add(new User("Bob", 25));
        users.add(new User("Charlie", 30));

        users.forEach(System.out::println);
        // 输出 (按姓名降序):
        // User{name='Charlie', age=30}
        // User{name='Bob', age=25}
        // User{name='Alice', age=30}
    }
}
```

### 4.5 TreeSet 相关应用示例

*   **对 `List` 元素排序并保留重复 (技巧性)**：
    `TreeSet` 本身会去重。如果希望对 `List` 中的元素排序，但又想保留重复的元素 (即原始 `List` 中有多少个重复元素，排序后结果中也应有多少个)，可以使用 `TreeSet` 结合一个特殊的 `Comparator`。这个 `Comparator` 在比较到两个元素“相等”(例如，字符串内容相同) 时，不返回 0，而是返回一个固定的非零值 (如 1)，这样 `TreeSet` 就会认为它们是“不同”的元素，从而都保留下来。但请注意，这使得 `TreeSet` 内部的“相等”判断与元素的实际 `equals()` 方法不一致，主要用于排序和保留所有原始项的场景。

    ```java
    import java.util.ArrayList;
    import java.util.Comparator;
    import java.util.List;
    import java.util.TreeSet;
    
    public class SortListKeepDuplicates {
        public static void sortList(List<String> list) {
            // Comparator: 内容相同也视为不同 (返回1)，以保留重复项
            // 同时按字符串自然顺序排序
            Comparator<String> keepDuplicatesComparator = new Comparator<String>() {
                @Override
                public int compare(String s1, String s2) {
                    int cmp = s1.compareTo(s2);
                    return (cmp == 0) ? 1 : cmp; // 如果内容相同，返回1，使TreeSet不认为它们是同一个元素
                }
            };
    
            TreeSet<String> ts = new TreeSet<>(keepDuplicatesComparator);
            ts.addAll(list); // 添加所有元素到TreeSet进行排序和“去重”(实际是保留)
    
            list.clear();    // 清空原list
            list.addAll(ts); // 将排序后的结果加回list
        }
    
        public static void main(String[] args) {
            List<String> names = new ArrayList<>();
            names.add("Eve");
            names.add("Alice");
            names.add("Bob");
            names.add("Alice"); // 重复
            names.add("David");
            names.add("Alice"); // 重复
    
            System.out.println("Original list: " + names);
            sortList(names);
            System.out.println("Sorted list (duplicates kept): " + names);
            // 输出: Sorted list (duplicates kept): [Alice, Alice, Alice, Bob, David, Eve]
        }
    }
    ```
    **注意**：这种方法虽然能达到排序并保留重复的效果，但 `TreeSet` 的主要设计目的还是存储唯一且有序的元素。如果频繁需要此类操作，可能需要考虑其他数据结构或排序算法。
