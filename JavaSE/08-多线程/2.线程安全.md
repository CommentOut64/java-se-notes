## 5. 线程安全问题

### 5.1 共享资源与线程安全

*   **局部变量**：线程私有，不共享，无线程安全问题。
*   **不同对象的实例变量**：不共享，无线程安全问题。
*   **静态变量**：所有对象共享，多线程并发修改时易产生线程安全问题。
*   **同一对象的实例变量**：通过`Runnable`或将对象传递给多个`Thread`时共享，多线程并发修改时易产生线程安全问题。

**问题示例：卖票（使用`Runnable`共享`ticket`）**

```java
class TicketSaleRunnable implements Runnable {
    private int ticket = 100; // 共享资源

    @Override
    public void run() {
        while (true) {
            if (ticket > 0) {
                try {
                    Thread.sleep(10); // 模拟网络延迟，放大问题
                } catch (InterruptedException e) {
                    e.printStackTrace();
                }
                System.out.println(Thread.currentThread().getName() + " 卖出一张票，票号:" + ticket--);
            } else {
                break;
            }
        }
    }
}

public class SaleTicketUnsafe {
    public static void main(String[] args) {
        TicketSaleRunnable tr = new TicketSaleRunnable();
        Thread t1 = new Thread(tr, "窗口一");
        Thread t2 = new Thread(tr, "窗口二");
        Thread t3 = new Thread(tr, "窗口三");

        t1.start();
        t2.start();
        t3.start();
        // 可能出现重复票或票号为负数的问题
    }
}
```

上述代码由于多个线程并发修改`ticket`变量（`ticket--`不是原子操作，`if(ticket > 0)`和`ticket--`之间也可能被切换），会导致线程安全问题，如卖出重复的票或票数统计错误。

### 5.2 同步机制解决线程安全问题

Java使用`synchronized`关键字或`Lock`接口实现同步，确保同一时刻只有一个线程能访问被保护的共享资源代码块。

#### 5.2.1 `synchronized`关键字

**同步代码块**：

```java
synchronized(同步锁对象){
     // 需要同步操作的代码
}
```

**同步方法**：

```java
public synchronized void method(){
    // 可能产生线程安全问题的代码
}
```

**锁对象**：

*   **同步代码块**：手动指定，必须是所有竞争线程共享的唯一对象。
*   **非静态同步方法**：锁对象是`this`（当前实例对象）。
*   **静态同步方法**：锁对象是当前类的`Class`对象（例如 `ClassName.class`）。

**解决线程安全问题的思考顺序**：

1.  **识别问题**：确定多线程运行的代码、共享数据、以及操作共享数据的多条语句。
2.  **确定同步范围**：将操作共享数据的多条语句（原子操作单元）放入同步块。
    *   范围太小：-法解决安全问题。
    *   范围太大：影响并发效率。

**示例：使用`synchronized`方法解决卖票问题**

```java
class TicketSaleRunnableSafe implements Runnable {
    private int ticket = 100;
    private final Object lock = new Object(); // 可以使用任意共享对象作为锁

    @Override
    public void run() {
        while (true) {
            if (!saleOneTicket()) {
                break;
            }
        }
    }

    // 使用同步方法 (锁是this，即TicketSaleRunnableSafe的实例tr)
    private synchronized boolean saleOneTicket() {
    // 或者使用同步代码块：
    // private boolean saleOneTicket() {
    //    synchronized (lock) { // 或者 synchronized (this)
            if (ticket > 0) {
                try {
                    Thread.sleep(10);
                } catch (InterruptedException e) {
                    e.printStackTrace();
                }
                System.out.println(Thread.currentThread().getName() + " 卖出一张票，票号:" + ticket--);
                return true;
            } else {
                return false;
            }
    //    } // 同步代码块结束
    }
}

public class SaleTicketSafeSync {
    public static void main(String[] args) {
        TicketSaleRunnableSafe tr = new TicketSaleRunnableSafe();
        Thread t1 = new Thread(tr, "窗口一");
        Thread t2 = new Thread(tr, "窗口二");
        Thread t3 = new Thread(tr, "窗口三");

        t1.start();
        t2.start();
        t3.start();
    }
}
```

### 5.3 单例设计模式的线程安全问题

#### 5.3.1 饿汉式

类加载时即创建实例，天生线程安全。

```java
// 形式一：静态常量
public class HungrySingleton {
    private static final HungrySingleton INSTANCE = new HungrySingleton();
    private HungrySingleton(){}
    public static HungrySingleton getInstance(){
        return INSTANCE;
    }
}

// 形式二：枚举 (更推荐，防止反射和序列化破坏单例)
enum EnumSingleton {
    INSTANCE;
    // 可以添加方法
    public void doSomething() { System.out.println("EnumSingleton doing something."); }
}
```

#### 5.3.2 懒汉式

第一次调用`getInstance()`时创建实例，需要处理线程安全问题。

**线程不安全的懒汉式：**

```java
public class LazySingletonUnsafe {
    private static LazySingletonUnsafe instance;
    private LazySingletonUnsafe(){}
    public static LazySingletonUnsafe getInstance(){
        if(instance == null){ // 多线程并发时可能创建多个实例
            instance = new LazySingletonUnsafe();
        }
        return instance;
    }
}
```

**线程安全的懒汉式：**

1.  **同步方法** (效率较低)：

    ```java
    public class LazySingletonSyncMethod {
        private static LazySingletonSyncMethod instance;
        private LazySingletonSyncMethod(){}
        public static synchronized LazySingletonSyncMethod getInstance(){
            if(instance == null){
                instance = new LazySingletonSyncMethod();
            }
            return instance;
        }
    }
    ```

2.  **双重检查锁定 (DCL - Double-Checked Locking)** (推荐，需配合`volatile`)：

    ```java
    public class LazySingletonDCL {
        private static volatile LazySingletonDCL instance; // volatile防止指令重排
        private LazySingletonDCL(){}
        public static LazySingletonDCL getInstance(){
            if(instance == null){ // 第一次检查
                synchronized(LazySingletonDCL.class){
                    if(instance == null){ // 第二次检查
                        instance = new LazySingletonDCL();
                    }
                }
            }
            return instance;
        }
    }
    ```

3.  **静态内部类** (推荐，线程安全且延迟加载)：

    ```java
    public class LazySingletonStaticInner {
        private LazySingletonStaticInner(){}
        private static class Inner {
            static final LazySingletonStaticInner INSTANCE = new LazySingletonStaticInner();
        }
        public static LazySingletonStaticInner getInstance(){
            return Inner.INSTANCE;
        }
    }
    ```

### 5.4 死锁

多个线程各自占有一些共享资源，并互相等待对方释放自己需要的资源，导致所有线程都无法继续执行的现象。

**诱发死锁的四个必要条件：**

1.  **互斥条件**：资源在同一时间只能被一个线程占用。
2.  **请求与保持条件**：线程已保持了至少一个资源，但又提出了新的资源请求，而该资源已被其他线程占用。
3.  **不可剥夺条件**：线程已获得的资源在未使用完之前，不能被强行剥夺。
4.  **循环等待条件**：存在一个线程——资源的循环等待链。

**避免死锁**：破坏上述一个或多个条件。常见策略是按固定顺序获取锁。

**示例：简单的死锁**

```java
public class DeadLockDemo {
    private static final Object resourceA = new Object();
    private static final Object resourceB = new Object();

    public static void main(String[] args) {
        new Thread(() -> {
            synchronized (resourceA) {
                System.out.println(Thread.currentThread().getName() + " 获取 resourceA");
                try { Thread.sleep(100); } catch (InterruptedException e) { e.printStackTrace(); }
                System.out.println(Thread.currentThread().getName() + " 尝试获取 resourceB");
                synchronized (resourceB) {
                    System.out.println(Thread.currentThread().getName() + " 获取 resourceB");
                }
            }
        }, "线程1").start();

        new Thread(() -> {
            synchronized (resourceB) { // 注意获取锁的顺序与线程1相反
                System.out.println(Thread.currentThread().getName() + " 获取 resourceB");
                try { Thread.sleep(100); } catch (InterruptedException e) { e.printStackTrace(); }
                System.out.println(Thread.currentThread().getName() + " 尝试获取 resourceA");
                synchronized (resourceA) {
                    System.out.println(Thread.currentThread().getName() + " 获取 resourceA");
                }
            }
        }, "线程2").start();
    }
}
```

### 5.5 `Lock`接口(JDK5.0新特性)

`java.util.concurrent.locks.Lock` 接口提供了比 `synchronized` 更灵活的锁机制。常用实现类是 `ReentrantLock`（可重入锁）。

**`Lock` 的使用结构：**

```java
import java.util.concurrent.locks.Lock;
import java.util.concurrent.locks.ReentrantLock;

class SharedResource {
    private final Lock lock = new ReentrantLock();

    public void performAction() {
        lock.lock(); // 获取锁
        try {
            // 需要同步的代码
            System.out.println(Thread.currentThread().getName() + " 正在执行操作...");
            Thread.sleep(100); // 模拟操作耗时
        } catch (InterruptedException e) {
            e.printStackTrace();
        } finally {
            lock.unlock(); // 必须在finally块中释放锁
        }
    }
}
```

**示例：使用`ReentrantLock`解决卖票问题**

```java
import java.util.concurrent.locks.Lock;
import java.util.concurrent.locks.ReentrantLock;

class TicketSaleRunnableWithLock implements Runnable {
    private int ticket = 100;
    private final Lock lock = new ReentrantLock();

    @Override
    public void run() {
        while (true) {
            lock.lock(); // 加锁
            try {
                if (ticket > 0) {
                    try {
                        Thread.sleep(10);
                    } catch (InterruptedException e) {
                        e.printStackTrace();
                    }
                    System.out.println(Thread.currentThread().getName() + " 卖出一张票，票号:" + ticket--);
                } else {
                    break; // 票卖完了，退出循环
                }
            } finally {
                lock.unlock(); // 确保在finally中释放锁
            }
        }
    }
}

public class SaleTicketSafeLock {
    public static void main(String[] args) {
        TicketSaleRunnableWithLock tr = new TicketSaleRunnableWithLock();
        Thread t1 = new Thread(tr, "窗口一");
        Thread t2 = new Thread(tr, "窗口二");
        Thread t3 = new Thread(tr, "窗口三");

        t1.start();
        t2.start();
        t3.start();
    }
}
```

**`synchronized` 与 `Lock` 的对比：**

| 特性               | `synchronized`                                        | `Lock` (例如 `ReentrantLock`)                                |
| :----------------- | :---------------------------------------------------- | :----------------------------------------------------------- |
| **锁的获取与释放** | 隐式，JVM自动管理（进入代码块获取，退出或异常时释放） | 显式，需要手动调用`lock()`和`unlock()`（通常在`finally`中释放） |
| **锁的类型**       | 代码块锁、方法锁                                      | 仅代码块锁                                                   |
| **中断响应**       | 不可中断等待                                          | 可中断等待 (`lockInterruptibly()`)                           |
| **公平性**         | 非公平锁（可配置为公平锁，但通常不直接暴露）          | 可配置为公平锁或非公平锁（`ReentrantLock`构造器参数）        |
| **尝试获取锁**     | 不支持                                                | 支持超时获取 (`tryLock(time, unit)`) 或非阻塞获取 (`tryLock()`) |
| **条件变量**       | 配合`Object`的`wait()`, `notify()`, `notifyAll()`     | 配合`Condition`对象 (`newCondition()`)，更灵活               |
| **性能**           | JDK1.6后优化良好，与`Lock`在多数情况下性能相近        | 早期版本或特定高竞争场景下可能性能更优，提供更多控制         |
| **易用性**         | 简单易用                                              | 相对复杂，需要更小心地管理锁的释放                           |

*   优先考虑`synchronized`，因其简单且不易出错。
*   当需要更高级的功能（如可中断锁、尝试锁、公平锁、多个条件变量）时，使用`Lock`。
*   在选择时，通常顺序：`Lock` (若需高级特性) -> 同步代码块 (`synchronized`) -> 同步方法 (`synchronized`)。
