## 7. 线程间通信

### 7.1 通信的必要性与等待唤醒机制

当多个线程协同完成任务，并期望它们按特定规则有序执行时，就需要线程间的通信机制来协调工作。例如，生产者线程生产数据，消费者线程处理数据，消费者必须等待生产者完成生产。这种协调依赖于“等待唤醒机制”。

*   `wait()`: 使当前线程进入等待状态（`WAITING` 或 `TIMED_WAITING`），并释放持有的锁。线程进入与锁对象关联的“等待集”（wait set），不再参与 CPU 调度，直到被其他线程唤醒或等待超时。
*   `notify()`: 唤醒在此锁对象等待集中的**一个**线程。被唤醒的线程将尝试重新获取锁，成功后从 `wait()` 的地方继续执行。
*   `notifyAll()`: 唤醒在此锁对象等待集中的**所有**线程。

> **重要说明**：
> 被唤醒的线程并不能立即执行，它需要重新竞争锁。
>
> *   若成功获取锁，线程状态从 `WAITING`/`TIMED_WAITING` 变为 `RUNNABLE`。
> *   若未获取锁（例如锁被其他线程持有），线程状态将变为 `BLOCKED`。

#### `wait()`与`notify()`使用注意事项

1.  **同一锁对象**：`wait()` 方法与 `notify()`/`notifyAll()` 方法必须由**同一个锁对象**调用。
2.  **`Object` 类的方法**：这些方法属于 `java.lang.Object` 类，因为任何对象都可以作为锁。
3.  **同步环境**：`wait()`, `notify()`, `notifyAll()` 必须在`synchronized`同步代码块或同步方法中使用，因为它们操作的是特定对象的锁和等待集。否则会抛出 `IllegalMonitorStateException`。

**示例：线程交替打印**

使用两个线程交替打印数字 1 到 20。

```java
package com.example.threadcommunication;

class AlternatingPrinter implements Runnable {
    private int number = 1;
    private static final int MAX_NUMBER = 20; // 减少打印上限，便于观察

    @Override
    public void run() {
        while (true) {
            synchronized (this) { // 使用当前对象作为锁
                // 唤醒可能在等待的另一个线程
                this.notify();

                if (number <= MAX_NUMBER) {
                    System.out.println(Thread.currentThread().getName() + ": " + number++);
                } else {
                    // 确保另一个线程也被唤醒以检查退出条件
                    // this.notify(); // 可选：在退出前再次唤醒，防止对方永久等待
                    break; // 结束循环
                }

                try {
                    // 如果数字还没打印完，当前线程等待，并释放锁
                    if (number <= MAX_NUMBER) {
                        this.wait();
                    }
                } catch (InterruptedException e) {
                    Thread.currentThread().interrupt(); // 恢复中断状态
                    System.err.println(Thread.currentThread().getName() + " interrupted.");
                }
            }
        }
    }
}

public class AlternatingPrintDemo {
    public static void main(String[] args) {
        AlternatingPrinter printer = new AlternatingPrinter();
        Thread t1 = new Thread(printer, "线程A");
        Thread t2 = new Thread(printer, "线程B");

        t1.start();
        t2.start();
    }
}
```

*注意：上述简单示例在某些极端情况下（如一个线程先结束）可能导致另一个线程永久等待。更健壮的实现通常会使用 `notifyAll()` 并在 `wait()` 调用外层使用 `while` 循环检查条件（防止虚假唤醒），或使用更高级的并发工具。*

### 7.2 生产者-消费者问题

生产者-消费者问题描述了共享固定大小缓冲区的生产者线程和消费者线程的同步问题。关键在于：

*   生产者在缓冲区满时不能继续生产（应等待）。
*   消费者在缓冲区空时不能继续消费（应等待）。

此问题涉及：

1.  **线程安全**：共享缓冲区的数据访问需要同步。
2.  **线程协调**：通过等待唤醒机制确保正确的生产和消费顺序。

**代码实现（简化版）：**

```java
package com.example.producerconsumer;

// 资源类：店员 (Clerk)，管理产品库存
class Clerk {
    private int productCount = 0;
    private static final int MAX_PRODUCTS = 5; // 缓冲区最大容量

    // 生产产品
    public synchronized void produceProduct() {
        while (productCount >= MAX_PRODUCTS) { // 使用while防止虚假唤醒
            System.out.println("产品已满！生产者(" + Thread.currentThread().getName() + ")等待。当前库存：" + productCount);
            try {
                wait();
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
                e.printStackTrace();
            }
        }
        productCount++;
        System.out.println("生产者(" + Thread.currentThread().getName() + ")生产了第 " + productCount + " 个产品。");
        notifyAll(); // 唤醒所有等待的线程（可能是消费者）
    }

    // 消费产品
    public synchronized void consumeProduct() {
        while (productCount <= 0) { // 使用while防止虚假唤醒
            System.out.println("产品已空！消费者(" + Thread.currentThread().getName() + ")等待。当前库存：" + productCount);
            try {
                wait();
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
                e.printStackTrace();
            }
        }
        System.out.println("消费者(" + Thread.currentThread().getName() + ")消费了第 " + productCount + " 个产品。");
        productCount--;
        notifyAll(); // 唤醒所有等待的线程（可能是生产者）
    }
}

// 生产者线程
class Producer extends Thread {
    private Clerk clerk;
    public Producer(Clerk clerk, String name) {
        super(name);
        this.clerk = clerk;
    }
    @Override
    public void run() {
        for (int i = 0; i < 10; i++) { // 生产10次
            clerk.produceProduct();
            // try { Thread.sleep(10); } catch (InterruptedException e) { e.printStackTrace(); } // 模拟生产耗时
        }
    }
}

// 消费者线程
class Consumer extends Thread {
    private Clerk clerk;
    public Consumer(Clerk clerk, String name) {
        super(name);
        this.clerk = clerk;
    }
    @Override
    public void run() {
        for (int i = 0; i < 10; i++) { // 消费10次
            clerk.consumeProduct();
            // try { Thread.sleep(20); } catch (InterruptedException e) { e.printStackTrace(); } // 模拟消费耗时
        }
    }
}

public class ProducerConsumerTest {
    public static void main(String[] args) {
        Clerk clerk = new Clerk();
        Producer p1 = new Producer(clerk, "P1");
        Consumer c1 = new Consumer(clerk, "C1");
        // Consumer c2 = new Consumer(clerk, "C2"); // 可以有多个消费者

        p1.start();
        c1.start();
        // c2.start();
    }
}
```

### 7.3 `sleep()`与`wait()`的比较

| 特性         | `Thread.sleep(long millis)`                                  | `Object.wait(long timeout)` 或 `wait()`                      |
| :----------- | :----------------------------------------------------------- | :----------------------------------------------------------- |
| **所属类**   | `java.lang.Thread`                                           | `java.lang.Object`                                           |
| **使用环境** | 任何地方                                                     | 必须在同步代码块或同步方法中（即获取到对象的锁之后）         |
| **锁的释放** | **不释放**锁。若在同步方法/块中调用，线程休眠期间仍持有锁。  | **释放**锁。线程进入等待状态，允许其他线程获取该对象的锁。   |
| **唤醒方式** | 休眠时间到期自动唤醒。                                       | 1. 其他线程调用同一对象的 `notify()` 或 `notifyAll()` 方法唤醒。<br>2. 若调用 `wait(timeout)`，则超时后自动唤醒。<br>3. 线程被中断 (`interrupt()`)。 |
| **主要用途** | 使当前线程暂停执行一段时间，常用于控制执行速率或等待外部条件。 | 用于线程间的协作和通信，实现等待某个条件成立。               |
| **异常处理** | 必须捕获或声明 `InterruptedException`。                      | 必须捕获或声明 `InterruptedException`。                      |

### 7.4 同步锁的释放与不释放场景

线程在执行同步代码时，何时会释放对同步监视器（锁）的锁定：

**释放锁的操作：**

*   当前线程的同步方法或同步代码块执行完毕。
*   在同步方法或代码块中遇到 `break` 或 `return` 语句，导致方法或代码块提前结束。
*   在同步方法或代码块中出现未处理的 `Error` 或 `Exception`，导致线程异常终止。
*   在同步方法或代码块中执行了锁对象的 `wait()` 方法，当前线程被挂起并释放锁。

**不会释放锁的操作：**

*   线程在同步方法或代码块中调用 `Thread.sleep()` 或 `Thread.yield()` 方法暂停执行。
*   线程在执行同步代码块时，被其他线程调用了该线程的 `suspend()` 方法（`suspend()` 已过时，易导致死锁，不推荐使用）。
