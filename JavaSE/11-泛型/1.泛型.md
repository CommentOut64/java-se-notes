## 1. 泛型概述

### 1.1 什么是泛型

泛型 (Generics) 即“类型参数化”(Parameterized Type)，允许在定义类、接口、方法时使用一个占位符 (如 `<T>`) 来代表未知的具体数据类型。这个具体的类型在实际使用时 (如创建对象或调用方法)才被指定。

例如，`List<String>` 中的 `<String>` 就是一个类型实参，它告诉编译器这个 `List` 只能存储 `String` 类型的对象。

### 1.2 为什么使用泛型

引入泛型的主要目的是提高代码的质量和开发效率：

*   **类型安全**：泛型将类型检查从运行时提前到编译时。如果程序在编译时没有警告，运行时通常就不会产生 `ClassCastException`。
*   **消除强制类型转换**：从泛型集合中获取元素时，不再需要手动进行类型转换，使代码更简洁。
*   **代码重用与可读性**：可以编写更通用的算法和数据结构，同时保持代码的清晰易懂。

例如，在 JDK 5.0 之前，集合类只能存储 `Object` 类型的元素，这既不安全也繁琐。泛型允许我们创建如 `List<String>` 这样的类型安全的集合。`java.lang.Comparable<T>` 和 `java.util.Comparator<T>` 接口也通过泛型来指定比较对象的类型。

## 2. 泛型的基本使用

### 2.1 在集合中使用泛型

泛型在集合框架中得到了广泛应用，大大增强了集合的类型安全性和易用性。

1.  **`ArrayList` 中使用泛型**：
    ```java
    // JDK 7+ 类型推断
    ArrayList<Integer> scoreList = new ArrayList<>();
    scoreList.add(90); // 自动装箱
    scoreList.add(85);
    // scoreList.add("高分"); // 编译错误，类型不匹配
    
    for (Integer score : scoreList) {
        System.out.println(score); // 无需强转
    }
    ```

2.  **`HashMap` 中使用泛型**：
    ```java
    HashMap<String, Integer> studentAges = new HashMap<>();
    studentAges.put("张三", 18);
    studentAges.put("李四", 19);
    // studentAges.put(20, "王五"); // 编译错误
    
    for (Map.Entry<String, Integer> entry : studentAges.entrySet()) {
        String name = entry.getKey();
        Integer age = entry.getValue();
        System.out.println(name + ": " + age);
    }
    ```

*   **类型推断**：从 JDK 7 开始，可以在构造函数中省略泛型类型参数，编译器会自动推断：`List<Integer> list = new ArrayList<>();`。
*   **引用类型**：泛型的类型参数只能是引用数据类型 (如 `Integer`, `String`)，不能是基本数据类型 (如 `int`, `double`)。需要使用对应的包装类。
*   **不指定泛型 (原始类型)**：如果在声明集合时不指定泛型 (如 `List list = new ArrayList()`)，则默认为 `Object` 类型。这种用法不推荐，因为它会丢失泛型带来的类型安全。

### 2.2 在比较器中使用泛型

`java.lang.Comparable<T>` 和 `java.util.Comparator<T>` 接口使用泛型来指定比较对象的类型，避免了类型转换和潜在的 `ClassCastException`。

**示例：`Rectangle` 类实现 `Comparable<Rectangle>` 按面积比较**

```java
class Rectangle implements Comparable<Rectangle> {
    private double length;
    private double width;

    public Rectangle(double length, double width) {
        this.length = length;
        this.width = width;
    }

    public double getArea() {
        return length * width;
    }

    @Override
    public String toString() {
        return "Rectangle[length=" + length + ", width=" + width + ", area=" + getArea() + "]";
    }

    @Override
    public int compareTo(Rectangle other) {
        // 按面积比较
        return Double.compare(this.getArea(), other.getArea());
    }
}

// 测试
public class TestRectangleSort {
    public static void main(String[] args) {
        Rectangle[] arr = {
            new Rectangle(6, 2), // 12
            new Rectangle(4, 3), // 12
            new Rectangle(5, 4)  // 20
        };
        java.util.Arrays.sort(arr); // 无需强转，类型安全
        for (Rectangle r : arr) {
            System.out.println(r);
        }
    }
}
```
在未使用泛型时，`Comparator` 的 `compare` 方法参数是 `Object`，需要手动强转，且可能在传入非预期类型时导致运行时错误。使用泛型后，编译器会进行类型检查。

## 3. 自定义泛型

除了使用 JDK 提供的泛型类型外，我们还可以定义自己的泛型类、泛型接口和泛型方法。

### 3.1 自定义泛型类与泛型接口

当类或接口中的某些成员 (如属性、方法参数、返回值) 的类型需要在创建实例或实现接口时才能确定，就可以使用泛型。

#### 1. 声明与使用

*   泛型类：`public class Box<T> { private T content; ... }`
*   泛型接口：`public interface Generator<T> { T next(); }`
*   类型参数 `<T>` (或其他大写字母如 `E`, `K`, `V`) 在类或接口内部代表一个未知的类型。

> ### 1. 单一字母约定
>
> 1. **`<T>`（Type）**
>
>    最常见的通用类型（Type）占位符，用于表示“某种类型”，尤其在编写**与类型无关的通用工具类或方法**时。
>
> 2. **`<E>`（Element）**
>
>    多用于集合框架里，表示集合（Collection）中的元素类型（Element）。
>
> 3. **`<K, V>`（Key, Value）**
>
>    通常用在键值对（Map、Dictionary）或类似结构中：`K` 表示键（Key），`V` 表示值（Value）。
>
> 4. **`<N>`（Number）**
>
>    有时用于表示数字类型（Number）的范围，例如对数字做各种运算的泛型方法可能会使用 `<N extends Number>`。
>
> ### 2. 多类型参数与后续字母约定
>
> 1. **`<T, U, V>` 或 `<T1, T2>`**
>
>    当一个类或方法需要定义多个无特定含义的类型参数时，可按顺序使用 T、U、V，或加上数字后缀 T1、T2，以示区分。
>
> 2. **`<S, T>` 或 `<A, B>`**
>
>    有时为了语义更清晰（而不仅仅是“第一种类型”、“第二种类型”），可以选用连续字母（例如：`S`、`T` 表示 Source、Target；`A`、`B` 表示两种“类型 A”与“类型 B”）。不过，此时仍建议在文档或注释中说明 S、T、A、B 的具体含义。
>
> ### 3. 可读性更强的命名——“全称”风格
>
> - 当一个类型参数含义比较特殊、用途较为明确时，为了增强可读性，可使用更具描述性的名称，例如 `<E extends Employee>`、`<TKey>`、`<TValue>`，或直接 `<Entity>`、`<Dto>`。
> - 特别是在项目中，若业务场景复杂、类或方法本身不止一个泛型，采用更具语义的名称会让后续维护更方便。

*   实例化时指定具体类型：`Box<String> stringBox = new Box<>();`

    若不指定类型参数 (原始类型)，则默认为 `Object`，但不推荐。

#### 2. 继承与实现泛型结构

*   子类可以指定父类泛型参数的具体类型：
    `class StringBox extends Box<String> { ... }`
*   子类也可以不指定，继续使用泛型 (擦除或传递)：
    `class GenericBox<T> extends Box<T> { ... }` (保留父类泛型)
    `class RawBox extends Box { ... }` (等同于 `Box<Object>`)
*   子类可以在父类泛型的基础上增加新的泛型参数：
    `class AdvancedBox<T, U> extends Box<T> { private U metadata; ... }`

#### 3. 注意事项

*   泛型参数不能是基本数据类型。

*   类的泛型参数不能用于静态成员 (静态变量、静态方法)。因为静态成员属于类本身，在类加载时就需要确定，而泛型类型是在对象创建时确定的。

*   不能创建泛型数组，如 `T[] array = new T[10];` (编译错误)。

    可以通过 `T[] array = (T[]) new Object[10];` 创建，但这不安全。推荐使用 `List<T>`。

*   异常类不能是泛型的。

**示例：`Student<S>` 类，成绩类型可变**

```java
class Student<S> { // S 代表成绩的类型
    private String name;
    private S score;

    public Student(String name, S score) {
        this.name = name;
        this.score = score;
    }

    @Override
    public String toString() {
        return "姓名：" + name + ", 成绩：" + score;
    }
}

public class TestStudent {
    public static void main(String[] args) {
        Student<String> s1 = new Student<>("小明", "优秀");
        Student<Double> s2 = new Student<>("小红", 95.5);
        Student<Character> s3 = new Student<>("小刚", 'A');
        System.out.println(s1);
        System.out.println(s2);
        System.out.println(s3);
    }
}
```

**示例：`DAO<T>` 类 (Data Access Object)**

`DAO<T>` 类用于操作特定类型 `T` 的数据对象。

```java
import java.util.*;

class User {
    private int id;
    private String name;
    // 构造器, getters, setters, toString, equals, hashCode 省略
    public User(int id, String name) { this.id = id; this.name = name; }
    @Override public String toString() { return "User{id=" + id + ", name='" + name + '\'' + '}'; }
}

class DAO<T> {
    private Map<String, T> map = new HashMap<>();

    // DAO 方法见下表
    public void save(String id, T entity) {
        if (!map.containsKey(id)) {
            map.put(id, entity);
        }
    }
    public T get(String id) {
        return map.get(id);
    }
    public void update(String id, T entity) {
        if (map.containsKey(id)) {
            map.put(id, entity);
        }
    }
    public List<T> list() {
        return new ArrayList<>(map.values());
    }
    public void delete(String id) {
        map.remove(id);
    }
}

public class DAOTest {
    public static void main(String[] args) {
        DAO<User> userDao = new DAO<>();
        userDao.save("1", new User(1, "张三"));
        userDao.save("2", new User(2, "李四"));
        System.out.println("All users: " + userDao.list());
        User user1 = userDao.get("1");
        System.out.println("User 1: " + user1);
        userDao.update("1", new User(1, "张三丰"));
        System.out.println("Updated User 1: " + userDao.get("1"));
        userDao.delete("2");
        System.out.println("After deleting User 2: " + userDao.list());
    }
}
```

`DAO<T>` 类的方法说明：

| 方法签名                           | 功能描述                                                     | 参数说明                                                     |
| ---------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| `void save(String id, T entity)`   | 保存 T 类型的对象到内部 Map 中，仅当 id 不存在时。           | `id`: 对象的唯一标识 (String), `entity`: 要保存的 T 类型对象 (T) |
| `T get(String id)`                 | 从 Map 中获取指定 id 对应的 T 类型对象。                     | `id`: 对象的唯一标识 (String)                                |
| `void update(String id, T entity)` | 替换 Map 中 key 为 id 的内容为 entity 对象，仅当 id 已存在时。 | `id`: 对象的唯一标识 (String), `entity`: 新的 T 类型对象 (T) |
| `List<T> list()`                   | 返回 Map 中所有 T 类型对象组成的列表。                       | 无                                                           |
| `void delete(String id)`           | 从 Map 中删除指定 id 对应的对象。                            | `id`: 对象的唯一标识 (String)                                |

### 3.2 自定义泛型方法

泛型方法是指在声明方法时定义了类型参数，该类型参数的作用域仅限于该方法。

泛型方法可以定义在普通类中，也可以定义在泛型类中。

**声明与使用：**

*   格式：`[访问权限] <泛型标识列表> 返回值类型 方法名([泛型标识 参数名称, ...]) [throws 异常]`
*   类型参数在调用方法时由编译器根据传入的实参类型自动推断。
*   泛型方法可以是**静态**的。
*   方法签名中的 `<T>` 表示这是一个泛型方法，它告诉编译器：在方法体内，`T` 是一个类型变量，可以被调用方根据传入的实参类型推断并绑定具体的类型。如果把 `<T>` 去掉，编译器就不知道 `T` 是什么类型，编译会报错。

**示例：**

1.  **数组元素交换**
    
    ```java
    public class ArrayUtil {
        public static <E> void swap(E[] array, int i, int j) {
            E temp = array[i];
            array[i] = array[j];
            array[j] = temp;
        }
    }
    
    // 调用
    Integer[] numbers = {1, 2, 3, 4};
    ArrayUtil.swap(numbers, 0, 2); // numbers 变为 {3, 2, 1, 4}
    
    String[] names = {"Alice", "Bob"};
    ArrayUtil.swap(names, 0, 1); // names 变为 {"Bob", "Alice"}
    ```
    
2.  **将数组元素添加到集合**
    
    ```java
    public static <T> void fromArrayToCollection(T[] a, Collection<T> c) {
        for (T element : a) {
            c.add(element);
        }
    }
    ```

### 3.3 类型擦除

Java 的泛型是通过**类型擦除** (Type Erasure) 实现的。这意味着在编译后，泛型类型信息会被移除 (擦除)，泛型参数会被替换为其上界 (如 `<T extends Number>` 的 `T` 被替换为 `Number`) 或 `Object` (如 `<T>` 的 `T` 被替换为 `Object`)。

例如，`List<String>` 和 `List<Integer>` 在编译后都会变成 `List`。JVM 在运行时并不知道泛型的具体类型参数。

这就是为什么：
*   不能获取泛型类型的运行时信息 (如 `list instanceof List<String>` 是非法的)。
*   不能创建泛型数组 (如 `new T[]`)。
*   静态上下文中不能引用类的泛型参数。

## 4. 泛型与继承

### 4.1 泛型类型的继承规则

一个重要的规则是：**如果 `B` 是 `A` 的子类型，那么 `G<B>` 并不是 `G<A>` 的子类型。**

例如，`String` 是 `Object` 的子类，但是 `List<String>` **不是** `List<Object>` 的子类。

```java
List<String> strList = new ArrayList<>();
// List<Object> objList = strList; // 编译错误！
```
如果上述赋值允许，那么就可以通过 `objList.add(new Integer(1))` 向 `strList` 中添加非 `String` 对象，这会破坏 `strList` 的类型安全。

### 4.2 与数组的协变性对比

数组的行为与泛型不同。如果 `Man` 是 `Person` 的子类，那么 `Man[]` **是** `Person[]` 的子类 (称为协变)。

```java
class Person {}
class Man extends Person {}

Man[] men = new Man[10];
Person[] persons = men; // 合法

// 但这可能导致运行时错误：
// persons[0] = new Person(); // 如果 Person 不是 Man，会抛出 ArrayStoreException
```
数组的协变性在某些情况下提供了便利，但也牺牲了编译时的类型安全。泛型通过不允许这种协变来保证更强的类型安全。

## 5. 通配符

当方法参数的类型是一个泛型类或接口，但我们不关心或无法确定具体的类型参数时，可以使用通配符 `?`。

### 5.1 无界通配符 `?`

`List<?>` (读作 "list of unknown") 表示一个持有某种未知类型的 `List`。它是 `List<String>`、`List<Integer>` 等所有具体泛型 `List` 的一种“父类型”(更准确地说，`List<?>` 类型的变量可以引用任何类型的 `List` 对象)。

**含义与基本使用：**

```java
public void printList(List<?> list) {
    for (Object elem : list) { // 只能安全地作为 Object 读取
        System.out.print(elem + " ");
    }
    System.out.println();
}

// 调用
List<Integer> li = Arrays.asList(1, 2, 3);
List<String>  ls = Arrays.asList("one", "two", "three");
printList(li);
printList(ls);
```

**读写限制：**

*   **读 (get)**：可以从 `List<?>` 中读取元素，但读取出的元素只能赋值给 `Object` 类型的变量。
*   **写 (add)**：**不能**向 `List<?>` 中添加任何元素 (除了 `null`)。因为编译器不知道 `?` 代表什么具体类型，无法保证类型安全。
    ```java
    List<?> unknownList = new ArrayList<String>();
    // unknownList.add("hello"); // 编译错误
    unknownList.add(null);    // 合法
    Object o = unknownList.get(0); // 合法
    ```

### 5.2 有界通配符

为了对通配符代表的类型进行限制，可以使用有界通配符。

**上限通配符：`<? extends UpperBoundType>` (协变)**

*   表示 `?` 是 `UpperBoundType` 或其任意子类型。
*   **读**：可以安全地读取元素，读取出的元素类型是 `UpperBoundType`。
*   **写**：**不能**添加任何元素 (除了 `null`)。因为不知道具体是哪个子类型。
*   适用于主要从结构中**读取**数据 (生产者) 的场景。

```java
public static double sumOfList(List<? extends Number> list) {
    double sum = 0.0;
    for (Number n : list) { // 可以安全地作为 Number 读取
        sum += n.doubleValue();
    }
    // list.add(new Integer(1)); // 编译错误，不能写入
    return sum;
}
List<Integer> ints = Arrays.asList(1, 2, 3);
System.out.println("Sum = " + sumOfList(ints)); // 输出 Sum = 6.0
List<Double> doubles = Arrays.asList(1.0, 2.5, 3.0);
System.out.println("Sum = " + sumOfList(doubles)); // 输出 Sum = 6.5
```

**下限通配符：`<? super LowerBoundType>` (逆变)**

*   表示 `?` 是 `LowerBoundType` 或其任意父类型 (直至 `Object`)。
*   **读**：只能安全地将读取出的元素赋值给 `Object` 类型的变量。
*   **写**：可以安全地添加 `LowerBoundType` 及其子类型的对象。
*   适用于主要向结构中**写入**数据 (消费者) 的场景。

```java
public static void addNumbers(List<? super Integer> list) {
    list.add(1); // 可以添加 Integer
    list.add(2);
    // Number n = list.get(0); // 编译错误，读取出的是 Object
    Object o = list.get(0); // 安全
}
List<Integer> intList = new ArrayList<>();
addNumbers(intList);
List<Number> numList = new ArrayList<>();
addNumbers(numList);
List<Object> objList = new ArrayList<>();
addNumbers(objList);
```

**PECS 原则 (Producer Extends, Consumer Super)**

这是一个助记法则，帮助决定使用哪种有界通配符：
*   **Producer Extends**: 如果你需要一个列表来产出 `T` 类型的数据 (你只想从中读取 `T`)，使用 `<? extends T>`。
*   **Consumer Super**: 如果你需要一个列表来消费 `T` 类型的数据 (你只想向其写入 `T`)，使用 `<? super T>`。
*   如果既要生产也要消费，通常不使用通配符，直接使用精确的泛型类型。

**读写总结 (以 `List` 为例):**

| 通配符类型          | 写入 (add) 操作 | 读取 (get) 操作 返回类型 |
| ------------------- | --------------- | ------------------------ |
| `List<T>`           | `T` 及其子类型  | `T`                      |
| `List<?>`           | `null`          | `Object`                 |
| `List<? extends T>` | `null`          | `T`                      |
| `List<? super T>`   | `T` 及其子类型  | `Object`                 |

### 5.3 通配符使用注意点

*   通配符 `?` 不能用于泛型方法声明时的类型参数列表 (如 `public static <?> void method(...)` 是错误的)。
*   通配符 `?` 不能用于泛型类的声明 (如 `class MyClass<?> { ... }` 是错误的)。
*   通配符 `?` 不能用于创建对象实例的右边 (如 `List<?> list = new ArrayList<?>();` 是错误的，应为 `new ArrayList<>()` 或具体类型)。
