## 1. JAR 文件 (Java Archive)

JAR 文件本质上是一个**压缩包**，遵循我们熟悉的 ZIP 文件格式。您可以把它理解为 Java 世界里的“安装包”或“工具箱”。

它主要用于：
*   将多个 `.class` 文件、配置文件、图片等资源打包成一个单独的文件，便于分发和部署。
*   作为第三方**库（Library）**供其他项目使用。
*   打包成一个可直接运行的 Java 应用程序。

每个 JAR 文件内部都包含一个名为 `META-INF/MANIFEST.MF` 的**清单文件**，它记录了该 JAR 包的元数据信息。

## 2. 创建基本的 JAR 文件

虽然现代的 IDE（如 IntelliJ IDEA）和构建工具（如 Maven）可以自动完成 JAR 的打包，但了解其手动创建过程有助于理解其工作原理。

### 2.1. 准备工作

首先，你需要将你的 `.java` 源文件编译成 `.class` 文件。

1.  **创建项目目录结构：**
    ```
    my-app/
    ├── src/
    │   └── com/
    │       └── example/
    │           └── HelloWorld.java
    └── out/  (用于存放编译后的 .class 文件)
    ```

2.  **编写源代码 (`HelloWorld.java`)：**
    ```java
    package com.example;
    
    public class HelloWorld {
        public static void main(String[] args) {
            System.out.println("Hello, JAR!");
        }
    }
    ```

3.  **编译代码：**
    打开命令行，进入 `my-app` 目录，执行以下命令将 `.java` 文件编译到 `out` 目录下。
    ```bash
    # -d 指定输出目录
    javac -d out src/com/example/HelloWorld.java
    ```
    执行后，`out` 目录下会生成 `com/example/HelloWorld.class` 文件。

### 2.2. 使用 `jar` 命令创建

`jar` 是 JDK 自带的命令行工具，用于创建和管理 JAR 文件。

*   **命令格式**：`jar [选项] [jar文件名] [要打包的文件/目录]`
*   **常用选项**：
    *   `c`：创建一个新的 JAR 文件 (create)。
    *   `v`：在标准输出中生成详细输出 (verbose)。
    *   `f`：指定 JAR 文件名 (file)。

在 `my-app` 目录下执行以下命令来创建一个名为 `HelloWorld.jar` 的文件：
```bash
# -C out . 表示切换到 out 目录，并打包该目录下的所有内容。
# 这样做可以避免在 JAR 中包含 out/ 这个父目录。
jar -cvf HelloWorld.jar -C out .
```
执行后，你就会在 `my-app` 目录下看到 `HelloWorld.jar` 文件。

## 3. 清单文件 (Manifest)

### 3.1. 什么是清单文件？

清单文件 `META-INF/MANIFEST.MF` 是 JAR 文件的“说明书”，它是一个文本文件，包含了键值对形式的元数据。

一个由 `jar` 命令自动生成的简单清单文件内容如下：
```manifest
Manifest-Version: 1.0
Created-By: 21.0.1 (Oracle Corporation)
```

### 3.2. 自定义清单文件

我们可以创建自己的清单文件来添加额外信息，其中最重要的一个属性是 `Main-Class`，它用于指定程序的入口点，是创建**可执行 JAR** 的关键。

1.  在 `my-app` 目录下创建一个名为 `manifest.txt` 的文本文件。
2.  在文件中写入以下内容：
    ```manifest
    Main-Class: com.example.HelloWorld
    
    ```
    > **极其重要**：文件末尾**必须**有一个换行符（即一个空行），否则最后一个属性可能会被忽略！

## 4. 创建可执行的 JAR 文件

### 4.1. 什么是可执行 JAR？

可执行 JAR 文件是一种可以通过 `java -jar` 命令直接运行的 JAR 包。它必须在清单文件中通过 `Main-Class` 属性指定哪个类是程序的入口（即包含 `main` 方法的类）。

### 4.2. 创建步骤

使用 `m` 选项来指定我们自定义的清单文件。

在 `my-app` 目录下执行以下命令：
```bash
# m 选项用于包含自定义清单文件中的信息
jar -cvfm ExecutableApp.jar manifest.txt -C out .
```

创建成功后，你就可以通过以下命令直接运行它了：
```bash
java -jar ExecutableApp.jar
```
**预期输出：**
```
Hello, JAR!
```

## 5. 多版本 JAR 文件 (Multi-Release JAR)

这是 Java 9 引入的一个高级特性，主要面向库的开发者。

### 5.1. 什么是多版本 JAR？

一个多版本 JAR 文件允许你在**同一个 JAR 包内，为不同版本的 Java 运行时（JRE）提供不同版本的类文件**。

### 5.2. 为什么需要它？

假设你开发了一个库，希望它能：
*   在旧的 Java 8 上正常运行。
*   当用户使用新的 Java 11 或更高版本时，能利用新版本 Java 提供的更高效的 API。

多版本 JAR 就可以实现这个目标。Java 8 会加载 JAR 中基础路径下的类文件，而 Java 11 会优先加载为其特定准备的版本。

### 5.3. 目录结构示例

多版本 JAR 的特定版本类文件存放在 `META-INF/versions/` 目录下。

```
my-multi-release-jar.jar
├── com/
│   └── example/
│       └── StringUtils.class  (这是给 Java 8 及以下版本使用的基础版本)
├── META-INF/
│   ├── MANIFEST.MF            (清单文件中必须包含 Multi-Release: true)
│   └── versions/
│       ├── 9/
│       │   └── com/
│       │       └── example/
│       │           └── StringUtils.class (这是给 Java 9 使用的特定版本)
│       └── 11/
│           └── com/
│               └── example/
│                   └── StringUtils.class (这是给 Java 11 及以上版本使用的特定版本)
```
*   当一个运行在 Java 11 上的程序使用这个 JAR 时，它会加载 `META-INF/versions/11/com/example/StringUtils.class`。
*   当一个运行在 Java 8 上的程序使用时，它会加载根目录下的 `com/example/StringUtils.class`。

对于新手而言，你只需要了解这个概念即可，在日常应用开发中较少直接创建此类 JAR。
